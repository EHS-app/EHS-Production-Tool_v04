# 2. Current `projects` schema

Defined in:

```text
lib/db/src/schema/projects.ts
```

```ts
export const projectsTable = pgTable(
  "projects",
  {
    id: uuid("id").primaryKey().defaultRandom(),

    userId: text("user_id").notNull(),

    name: text("name")
      .notNull()
      .default("Untitled"),

    venue: text("venue")
      .notNull()
      .default(""),

    client: text("client")
      .notNull()
      .default(""),

    data: jsonb("data")
      .notNull()
      .default({}),

    createdAt: timestamp("created_at", {
      withTimezone: true,
    })
      .notNull()
      .defaultNow(),

    updatedAt: timestamp("updated_at", {
      withTimezone: true,
    })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    index("projects_user_id_idx").on(table.userId),
  ],
);
```

## Database columns

| Column | PostgreSQL type | Required | Default |
|---|---|---:|---|
| `id` | UUID | Yes | Random UUID |
| `user_id` | Text | Yes | — |
| `name` | Text | Yes | `"Untitled"` |
| `venue` | Text | Yes | `""` |
| `client` | Text | Yes | `""` |
| `data` | JSONB | Yes | `{}` |
| `created_at` | Timestamp with timezone | Yes | Current time |
| `updated_at` | Timestamp with timezone | Yes | Current time |

The table has an index on `user_id`.

## Generated project types

```ts
export const insertProjectSchema =
  createInsertSchema(projectsTable).omit({
    id: true,
    createdAt: true,
    updatedAt: true,
  });

export type InsertProject =
  z.infer<typeof insertProjectSchema>;

export type ProjectRow =
  typeof projectsTable.$inferSelect;
```

Conceptually, the selected project type is:

```ts
type ProjectRow = {
  id: string;
  userId: string;
  name: string;
  venue: string;
  client: string;
  data: unknown;
  createdAt: Date;
  updatedAt: Date;
};
```

The `data` JSONB field currently contains most of the detailed Production Tool state. There is no separate normalized table for task-board data.

# 4. Existing task structures

There is currently **no app-domain task board structure**.

Specifically, the application does not currently contain:

- A `tasks` database table
- A `Task` TypeScript interface
- Task CRUD API routes
- A project-to-task relationship
- Task status or priority enums
- Task-board components

The Replit project tasks shown in the workspace are platform planning records. They are not stored in the application database and should not be mixed with the future Production Tool task board.

## Closest existing structure: brief assignments

Defined in:

```text
lib/db/src/schema/projectBriefs.ts
```

```ts
export const briefAssignmentsTable = pgTable(
  "brief_assignments",
  {
    id: text("id").primaryKey(),

    briefId: text("brief_id")
      .notNull()
      .references(() => projectBriefsTable.id, {
        onDelete: "cascade",
      }),

    freelancerUserId:
      text("freelancer_user_id").notNull(),

    crewId: text("crew_id")
      .notNull()
      .default(""),

    decision: text("decision")
      .notNull()
      .default("pending"),

    decidedAt: timestamp("decided_at", {
      withTimezone: true,
    }),

    acceptedSnapshot: jsonb("accepted_snapshot"),

    acceptedGigId: text("accepted_gig_id"),

    createdAt: timestamp("created_at", {
      withTimezone: true,
    })
      .notNull()
      .defaultNow(),

    updatedAt: timestamp("updated_at", {
      withTimezone: true,
    })
      .notNull()
      .defaultNow(),
  },
);
```

These records represent freelancer invitations and decisions, not general project tasks.

# 7. Best insertion points for a task board

## Option A: First-class sidebar view

This is the cleanest option for a complete task board.

Add a new view:

```ts
export type ShellView =
  | "oversikt"
  | "tasks"
  | "rigging"
  // ...
```

Add the navigation item in `buildNavGroups()`:

```ts
{
  id: "tasks",
  label: "Tasks",
  icon: ListTodo,
}
```

Then add a branch in `App.tsx` beside the existing overview and discipline views:

```tsx
{mainView === "tasks" && (
  <ProjectTaskBoard projectId={currentProjectId} />
)}
```

This gives the board its own full workspace and URL-like navigation state.

## Option B: Overview dashboard section

For a compact task summary, insert it into:

```text
artifacts/rigging-load-report/src/components/OverviewView.tsx
```

Possible structure:

```tsx
<OverviewView
  // Existing props
  taskSummary={taskSummary}
  onOpenTasks={() => setMainView("tasks")}
/>
```

Then render a small task section inside the overview:

```tsx
<ProjectTaskSummary
  tasks={taskSummary}
  onViewAll={() => onJump("tasks")}
/>
```

## Option C: Directly after `OverviewView`

A faster but less modular insertion would be:

```tsx
{mainView === "oversikt" && (
  <>
    <OverviewView {...overviewProps} />
    <ProjectTaskBoard projectId={currentProjectId} />
  </>
)}
```

This would place the full board below the overview, but it could make the overview page long and crowded.

## Recommended structure

For a full task board, the cleanest architecture is:

```text
lib/db/src/schema/projectTasks.ts
artifacts/api-server/src/routes/projectTasks.ts
artifacts/rigging-load-report/src/types/projectTask.ts
artifacts/rigging-load-report/src/hooks/use-project-tasks.ts
artifacts/rigging-load-report/src/components/ProjectTaskBoard.tsx
artifacts/rigging-load-report/src/components/ProjectTaskCard.tsx
```

Then add `"tasks"` to `ShellView` and render `ProjectTaskBoard` as a first-class `App.tsx` view.

This keeps tasks normalized and independently queryable instead of embedding the entire board inside the existing `projects.data` JSONB column.
